## 2) النشر (المرجع: docs/deployment.md)
الترتيب: بناء ← فحص ← نشر ← تحقق.
1. `opennextjs-cloudflare build` (الملف يشرح المتغيرات والاستثناءات).
2. فحوص ما قبل النشر: `tsc --noEmit`، `vitest run` للمجموعات الحرجة، `playwright` على بيئة staging مطابقة.
3. نشر Worker + ربط المتغيرات (Build-time vs Runtime per deployment.md).
4. تحقق بعد النشر:
   - `node scripts/healthcheck.mjs https://<domain>` (exit 0).
   - `SMOKE_EMAIL=... SMOKE_PASSWORD=... PLAYWRIGHT_BASE_URL=https://<domain> npx playwright test tests/e2e/post-deploy-smoke.spec.ts`
   - استعلام RPC قراءة واحدة وسجل دخول واحد.
   - `node scripts/verify-build-env.mjs <prod-supabase-url>` قبل النشر (المدقق يمنع حقن مشروع خاطئ).
5. تسجيل الأدلة: سجل النشر + استجابة الفحوص + وقت البدء/الانتهاء.

## 3) الترحيلات الإنتاجية
1. سرد الترحيلات المطلوبة من `supabase/migrations/` بترتيب أسمائها (يشمل `20261101090000_platform_admin_membership_guard.sql` المعتمد). الجرد الحالي (94 ملفًا) محفوظ في `evidence-r6-run10/results/migration-inventory.txt`.
2. **قبل**: نسخة قاعدة كاملة + عدّاد صفوف للجداول الحساسة (أدوار/صلاحيات/قيود/فترات).
3. **أثناء**: لا Staging في المسار المباشر المعتمد — التطبيق على الإنتاج في نافذة معلنة بعد نسخة كاملة. **تنبيه:** `deploy.yml` يبني وينشر ولا يطبّق ترحيلات؛ تطبيقها خطوة منفصلة تحتاج موافقة ومنفّذًا محددًا.
4. **بعد**: فحص `pg_policies` للجداول الحرجة، ‏`has_permission` دخان، ومطابقة العدادات.
5. **التراجع**: `..._rollback.sql` للترحيل الأخير؛ الترحيلات الأقدم تعتمد نسخة القاعدة الكاملة (لائحة في `docs/migrations/`).

## 4) النسخ الاحتياطي والاستعادة (البند 13)
- ‏RPO/RTO: **قرار مالك مطلوب** (توصية: ‏RPO ≤ 24h، ‏RTO ≤ 4h للمستأجر الواحد).
- التمرين الإلزامي قبل الإطلاق: استخراج نسخة من r6 → استعادة إلى بيئة معزولة → تحقق من العدادات والهوية (الصيغة identity-preserving).
- لا تُعد النسخ الاحتياطي مكتملًا حتى يوجد **سجل تمرين استعادة** ناجح.

## 5) المراقبة والتنبيهات (البند 14)
الحد الأدنى المقترح (لم يُنفَّذ):
- أخطاء التطبيق: تجميع أخطاء Server Actions + ‏RPC (مثل Sentry أو بديل).
- توافر: فحص HTTP خارجي كل دقيقة للمسارات العامة.
- قاعدة البيانات: اتصالات، استعلامات بطيئة (> 2s)، مساحة، قفل.
- الأمان: محاولات دخول فاشلة متكررة، واستدعاءات RPC مرفوضة بمعدل شاذ.
- وجهة التنبيه: قناة واحدة محددة + **شخص مسؤول ومناوب** (قرار مالك).
- كل تنبيه يجب أن يكون له إجراء في هذا الـRunbook.

## 6) مصفوفة التراجع (البند 15)
| المشكلة | الإجراء الفوري | التراجع | قرار |
|---|---|---|---|
| فشل النشر/الأصول | إعادة نشر الإصدار السابق (Cloudflare) | ‏Worker سابق + متغيرات ثابتة | منفّذ النشر |
| ترحيل خلل | إيقاف النشر | `_rollback.sql` أو استعادة النسخة الكاملة | مالك + ops |
| فشل إقفال سنة | الميزة معطلة خلف صلاحية | لا تراجع بيانات؛ القيد يُلغى فقط عبر مسار معتمد | مالك |
| فشل نسخ احتياطي | تنبيه + إيقاف الترحيلات | استعادة آخر نسخة سليمة | ops |
| تسريب أسرار | تدوير فوري | إبطال المفاتيح وإعادة النشر | مالك + ops |

## 7) التعامل مع فشل الإطلاق (Launch Failure)
1. إعلان الحالة (Incident) مع وقت البدء والمسؤول.
2. تجميد الترحيلات والنشر.
3. قرار: **Forward-fix** (إصلاح سريع ونشر) أم **Rollback** (العودة للإصدار السابق).
4. توثيق الجذر والزمن وإجراءات المنع قبل إعادة المحاولة.
5. لا يُعاد الإطلاق دون مراجعة معادية مختصرة للسبب الجذري.

## 8) الأدلة المطلوبة عند كل خطوة
- لقطة/سجل أوامر، نتيجة الفحوص، عدادات قبل/بعد، وقت وتوقيع المنفّذ.
- تُحفظ تحت `docs/progress/evidence-<env>-<date>/` بنفس تقاليد r6.

### ترتيب متغيرات Next.js (موثق)
`process.env` > `.env.<NODE_ENV>.local` > `.env.local` > `.env.<NODE_ENV>` > `.env`
(المصدر: `node_modules/next/dist/docs/01-app/02-guides/environment-variables.md`). env الصريح يتقدم دائمًا؛ و`.env.local` المحلي يتقدم على `.env.production` — سبب حادثة الحقن.
بوابة CI الجديدة: `PRODUCTION_SUPABASE_PROJECT_REF` إلزامي في بيئة `production`، ويجب أن يطابق `.env.production`، ثم `verify-build-env` بعد البناء قبل النشر.
