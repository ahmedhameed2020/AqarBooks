# إعداد المراقبة والتنبيهات — AqarBooks (PREPARED, NOT VERIFIED)

**الحالة:** إعداد موثق فقط. **لم تُثبت أي تنبيهات** — لا تدّعِ أنها تعمل حتى يصل تنبيه حقيقي إلى وجهته.
**المتاح اليوم:** `scripts/healthcheck.mjs` (‏exit 0 محليًا) + `observability.enabled: true` في `wrangler.jsonc`.

## 1) الإشارات المطلوبة
| الإشارة | المصدر | العتبة المقترحة | الإجراء عند التجاوز |
|---|---|---|---|
| تعطل الموقع | فحص HTTP خارجي كل 60s (`/en/login` 200) | 3 إخفاقات متتالية | تنبيه فوري + Rollback/تشخيص |
| بوابات المصادقة | `/en/dashboard` يجب أن يعيد 307 لزائر غير مسجل | 200 أو 5xx | تحقيق عاجل (بوابة مكسورة) |
| **فشل تسجيل الدخول** | سجلات Supabase Auth (أو عدّاد من `/token`) | > 20 فشل/5د من IP واحد أو > 100/ساعة | تنبيه + فحص محاولات تخمين؛ لا تُفعّل تخمين كلمات مرور |
| أخطاء الخادم | Cloudflare Observability / Logpush (5xx، استثناءات Worker) | أي 5xx متكرر > 5/5د | تنبيه + رابط السجل |
| أخطاء RPC المالية | لوج التطبيق (`[SEC-FAIL-CLOSED]`, RPC errors) | أي ظهور لـ`[SEC-FAIL-CLOSED]` | تحقيق فوري (قد يعني تعطّل تفويض) |
| الأداء | ‏p95 لمسارات المالية | > 2s لمدة 10د | تنبيه + مراجعة استعلامات |
| القاعدة | اتصالات، مساحة، استعلامات > 2s | حسب الحد | تنبيه + تصعيد |

## 2) الإعداد (يحتاج حسابك/موافقتك — لا إنشاء موارد مدفوعة هنا)
1. **فحص خارجي**: خدمة uptime (Cloudflare Health Checks أو مزود آخر) على `https://aqarbooks.com/en/login` و`/ar/login`.
2. **سجلات Cloudflare**: تفعيل Observability/Logpush إلى وجهة تحتفظ بالسجلات (مثل R2) مع تنبيه على 5xx.
3. **سجلات Auth**: تصدير سجلات Supabase Auth (أو قراءتها عند التحقيق) وضبط تنبيه على فشل الدخول المتكرر.
4. **وجهة التنبيه**: قناة واحدة (بريد/شات) + **مناوب محدد بالاسم** + تصعيد بعد 15 دقيقة بلا استجابة.
5. **إثبات العمل**: أوقف مسارًا عمدًا في بيئة معزولة (أو أرسل فشلًا اصطناعيًا) وتأكد من وصول التنبيه، ودوّن وقت الوصول.

## 3) ما لا يُدّعى
- لا تنبيهات مفعّلة اليوم. لا مناوب. لا جهة استلام.
- `wrangler.jsonc` يفعّل observability فقط (جمع)، لا تنبيهًا.
