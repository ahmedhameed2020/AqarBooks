# نطاق تأثير كل ترحيل والـbackfill على المؤسسات (مسودة للمراجعة)

محلي فقط. لم يُقرأ شيء من الإنتاج. المصدر: نصوص الترحيلات في `supabase/migrations/` (قراءة الترويسات والعبارات على مستوى الترحيل، وليس مراجعة سطر بسطر لكل دالة). **لم أقِس أي زمن قفل أو مسح على قاعدة حية**؛ الأعمدة «أثر القفل» تقدير من نوع العبارة وتحتاج قياسًا على نسخة من الإنتاج.

الرموز: **الكل** = كل المؤسسات الموجودة وقت التطبيق. **جديدة** = المؤسسات المنشأة بعد الترحيل فقط. **إعداد** = يلزم إجراء لكل مؤسسة تجريبية قبل أن تعمل الميزة.

## 2. ما يعتمد على حجم البيانات (يُقاس قبل النافذة)
1. **3a**: عدد صفوف `payment_allocations` و`payments` (الفحص 3 و4e). هذا يحدد زمن القفل. لا أملك رقمًا للإنتاج.
2. **1.1**: وجود قيمة `action` خارج القائمة (الفحص 4a) تُفشل الترحيل كاملًا (يتراجع وحده؛ لا ضرر بياني لكن النافذة تضيع).
3. **2f/2g**: وجود القيدين (الفحوص 4b و4c). غياب `access_events_reason_code_check` يُفشل 2g.
4. **3i**: بناء الفهرس على `payments` يحجب الكتابة.

## 3. إجراءات «إعداد» لكل مؤسسة تجريبية (لا تحدث تلقائيًا)
| الإجراء | بعد أي ترحيل | الأداة |
|---|---|---|
| اعتماد حساب المدينين لكل موقع | 2b | `set_default_receivable_account` (من يملك `finance.accounts.manage`) |
| وجود فترة محاسبية مفتوحة | 2d | `set_fiscal_period_status` |
| إنشاء حساب التزام «سلف العملاء» واعتماده (المؤسسات القائمة لا تملك 2250) | 3a/3b | إنشاء حساب ثم `set_default_customer_advance_account` |
| ربط حساب النقدية بخزينة أو إضافة حساب بنكي | الإيداع | `create_cashbox` / شاشة الحسابات البنكية |

## 4. ما لم يُفحص
زمن القفل الفعلي؛ أحجام الإنتاج؛ ما إذا كانت قاعدة الإنتاج عُدّلت يدويًا (الفحص 5 يقارن بصمات الدوال)؛ تعارض الترحيلات مع تغييرات إنتاج لم تدخل المستودع؛ سلوك `CREATE INDEX` الفعلي بوجود حمل.
