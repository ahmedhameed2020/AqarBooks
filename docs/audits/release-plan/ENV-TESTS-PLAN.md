## ترتيب مقترح عند الاعتماد
1. `final-hardening` (لا مساحة، بعد التعديل الصغير).
2. `role-permissions-rollout` عبر الأداة الرسمية (على C: فقط).
3. `demo-principal-capability` بعد زرع العرض، إن ثبت الشرط.
4. `gate-hardware-outbox-migration` أخيرًا وبموافقة منفصلة، لأنه الوحيد الذي ينشئ stack ويستهلك D:.

## ما أحتاج اعتماده
- تعديل شرط الاتصال في `final-hardening` (حارس العزل بدل المنفذ الثابت).
- تشغيل الأداة الرسمية للعنقود المؤقت (مجلد يزيله السكربت نفسه) — هل يُسمح أم تفضّل ألا يُنفَّذ حذف حتى من السكربت؟
- قرار: هل بوابات العتاد والعرض العام ضمن الإصدار؟
