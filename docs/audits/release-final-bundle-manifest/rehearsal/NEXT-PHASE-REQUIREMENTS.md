# متطلبات المرحلة التالية (قائمة فقط، لم يُنفَّذ شيء منها)

الحالة: G0 LOCAL CONDITIONALLY APPROVED (للقاعدة المحلية فقط). الإنتاج غير معتمد. أي بروفة أو تصدير أو استعادة يحتاج موافقة مستقلة وصريحة.

## قبل أي بروفة لاحقة (إلزامي)
1. `ON_ERROR_STOP=1` في كل ملف SQL منفّذ، وفشل مغلق عند أي خطأ (لا تكمل بعد خطأ).
2. مجلد إخراج جديد وفارغ لكل تشغيل (لا إعادة استخدام لمجلد فيه ملفات سابقة).
3. حارس RLS-GUARD وSEQ-GUARD وKEEP-GUARD مفعّلة، والتحقق منها قبل الكتابة (الترتيب: السطور 3–5 من export-run.psql، وأول \copy بعدها).
4. العزل: حاوية الاستعادة الفعلية (وليست حاوية الاختبار الحالية) تُختبر بالطريقة نفسها: مسارات، DNS، TCP خارجي، TCP إلى الحاويات الأخرى، مع اختبار إيجابي.
5. إثبات اكتمال النسخة المستخدمة للاستعادة، وليس الاكتفاء بمطابقة عدّين خاضعين لنفس RLS:
   - عدد الصفوف من مصدر مستقل بصلاحية تتجاوز RLS (لا من الدور نفسه)،
   - بصمة ملف النسخة (SHA-256) وحجمها،
   - قائمة الجداول والتسلسلات وقيمها من مصدر مستقل،
   - مطابقة سجل الترحيلات.
6. موافقة مستقلة وصريحة من المالك على كل تشغيل (لا تُفهم من موافقة سابقة).

## قبل أي اتصال بالإنتاج (منفصل، ولم يُعتمد)
- نص موافقة صريح باسم الإنتاج.
- قراءة فقط، بدور لا يملك كتابة، والدور لا يملك BYPASSRLS إلا بموافقة صريحة منفصلة (البديل D مفضل فلا حاجة إليه).
- تأكيد هوية القاعدة: هل «القاعدة الحالية» هي الإنتاج أم نسخة الاختبار؟ (ما زال مفتوحًا).

## أمور مفتوحة يجب حسمها أولًا
- حاوية `supabase_vector_aqarbooks` في حلقة إعادة تشغيل: سببها الأرجح DOCKER_HOST=http://host.docker.internal:2375 والمنفذ مغلق (انظر example-local/isolation/VECTOR-DIAGNOSIS-READONLY.txt). القرار للمالك.
- «Trakova»: لا يوجد أثر له على محرك Docker هذا. يحتاج المالك إلى تحديد المقصود.
- حاوية `g0_iso_test` متوقفة الآن (لم تُحذف)، والشبكة `g0_isolated_test_net` باقية (معزولة).
- البديل D: مفضّل، وتنفيذه يحتاج موافقة منفصلة.

## ما لا تشمله هذه القائمة
- لا تشغيل بروفة الآن، ولا تصدير، ولا استعادة، ولا اتصال بالإنتاج.
- لا تغيير لحزمة الإصدار المجمدة `ec1b669a…` ولا لخطة البروفة المعتمدة `25a3bbcb…`.
