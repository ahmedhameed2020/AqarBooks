== E. The read-only default is NOT a control (proved)
Role aqar_json_inventory (SELECT only, no ownership, no bypassrls), with a probe SECURITY DEFINER function that inserts into a probe table (created and dropped in TEST):
    step 1: plain call under the read-only default -> ERROR cannot execute INSERT in a read-only transaction; rows 0
    step 2: caller runs "set default_transaction_read_only = off", same call -> exit 0; rows 1
So the default can be switched off by the caller. The real control is the privilege set: no write grant and no executable definer that writes.
Residual risk: any FUTURE SECURITY DEFINER write function that is granted to PUBLIC would be reachable by this role. Fix requires REVOKE EXECUTE ... FROM PUBLIC on such functions, a global change: owner decision.
