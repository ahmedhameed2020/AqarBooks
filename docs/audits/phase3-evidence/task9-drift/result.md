## 2. Independent catalog comparison (new; `catalog_snapshot.sql`, `capture_run.py`)
A read-only SQL file reads schema `public` straight from the PostgreSQL catalogs, with `search_path` pinned to `pg_catalog` (so every definition renders fully qualified on both sides) and no OIDs: relations (kind, owner, RLS and FORCE RLS, options such as `security_invoker`, ACL), columns (type, nullability, defaults, identity, generated, collation, column ACL), constraints, indexes, view bodies, policies (command, permissive, roles, USING, WITH CHECK), triggers (definition, enabled state), functions (full definition, SECURITY DEFINER/INVOKER, config, volatility, leakproof, parallel, owner, ACL), enum/composite/domain types, sequences, default privileges, the schema's owner and ACL. It is deterministic (identical hash on repeated runs). `capture_run.py` runs one real `supabase db diff` and, as soon as the CLI prints "Diffing schemas" (all migrations applied, shadow still alive), snapshots the CLI's **shadow container** and the **live** stack database with that same file, then compares them. No image is pulled, nothing is written to a database.

The comparison therefore detects a real difference in every category it covers, and shows the shadow equal to live on the one run captured. **It was not captured on the reproduced-artifact instance** (that appeared in 1 of 7 loaded runs; no new load loops were run, as agreed), so the independent verification of that instance is NOT complete.

## 3. The verdict rule (revised after review) — `scripts/demo-local/drift-verdict.mjs`, `tests/drift-verdict.test.ts` (12 tests, pass)
* `CLEAN` (exit 0): the first two observations are both clean — nothing earlier.
* `DRIFT_REPRODUCED` (exit 1): two consecutive observations report the same difference — the tool repeated its report; this is **not** an independent proof that the schema differs.
* `UNSTABLE` (exit 2): anything else that ends a round, in particular **any difference or tool error followed by clean results** (`DRIFT → CLEAN → CLEAN`, `ERROR → CLEAN → CLEAN`, `CLEAN → DRIFT → CLEAN → CLEAN`), reports that never agree, or the cap of 6 observations. It is never turned into success automatically.
* Every observation (raw tool output included) and a `verdict.json` are saved to a folder whose path is printed (default under the system temp folder; `VERIFY_OUT_DIR` overrides). A tool failure is its own kind of observation and never counts as clean or as drift.
* Tested on the isolated stack with a **deliberate real difference** (probe table with RLS and a policy, plus a SECURITY DEFINER function granted to `anon`, removed afterwards): `verify` printed observation 1 differs, observation 2 differs, `DRIFT_REPRODUCED`, exit 1 (`verify-with-real-difference.txt`, `verify-outputs/…T04-57…`). It was not hidden by the retry. After removing the probe the live catalog is identical to the pre-probe one (after normalizing CRLF in my own capture files), and `verify` printed two clean observations, `CLEAN`, exit 0 (`verify-after-probe-removed.txt`). Unit tests cover the sequences above and a "real difference is never hidden by retrying" case.
* Residual weakness, stated: the rule cannot tell a tool artifact from a real difference when both look the same; `UNSTABLE` and `DRIFT_REPRODUCED` both require a human decision, and the catalog comparison (§2) is the independent way to make it.
