# 06 — Business Workflow Audit (end-to-end)

Audit of commit `a91d809` (master). Read-only static tracing of UI → server action → RPC/RLS → tables → accounting effect → audit → resulting UI. "Wired" means page → client component → exported server action or `.rpc()` that exists and has ≥1 caller. Every export in `lib/actions/*.ts` was scanned; only two are uncalled (`auth.ts:signUpAction` — deliberately dead; `property.ts:489 setUnitLeaseBillingRecipientAction` — dead). Accounting-effect detail is in `03-accounting-integrity.md`; authorization detail in `04-security-multitenancy.md`; onboarding in `07-saas-onboarding-commercial.md`.

## 1. Critical workflow traces

### 1.1 Issue due
UI `finance/dues/issue-due-form.tsx` → `issueDueAction` (`lib/actions/receivables.ts`) → `issue_dues` (baseline 5208; `finance.dues.issue`, units∈org+resort) → `dues` insert → trigger `trg_dues_01_tax_decision` → `trg_dues_post_to_ledger` → `post_due_to_ledger` (Dr AR / Cr revenue [+ Cr output VAT]) → `append_financial_audit_event('DUE_ISSUED')` → statement/aging/dashboard read from `dues` and views.
- Success: works; atomic (a posting failure rolls back the due).
- Failure states: no OPEN period → due created **without** journal entry, silently (ACC-08). Tax enforcement on + unmapped type → refused with `TAX_REVIEW_REQUIRED`.
- Duplicate: advisory lock + heuristic skip on (unit, type, issue date, description); no DB natural key. Double-click protected by `pending` state only (form idempotency key is a fresh `randomUUID()` per call).
- Bulk: `receivables.ts:104` sends `p_unit_ids: [single unit]` although the RPC takes an array — bulk issue is PARTIAL.
- Reversal: **no `void_due`/`cancel_due` exists**; the only correction is a credit note, which requires a tax decision and whose page is not in navigation (WF-02, WF-06, ACC-06).

### 1.2 Receive payment
UI `finance/payments/record-payment-form.tsx` (or `finance/cashier/*` → `payDueFromCashierAction`) → `recordPaymentAction` (`receivables.ts:139`) → `record_payment` (baseline 8092; `has_financial_permission('finance.payments.record')`) → `post_payment_internal`: cashier session validation, org advisory lock, idempotency check, receipt number (`next_sequence_value`), allocations with per-line over-allocation check, journal Dr cash/bank / Cr AR posted inline, `cash_transactions` RECEIPT row when in a cashier session → `platform_audit_logs` (no hash-chained `PAYMENT_CREATED` event, ACC-07) → payments list, receipt PDF (`lib/reports/payment-receipt-pdf.ts`), statements.
- Success: works end-to-end, receipt printing exists.
- Failure states: zod accepts `method: "POS"` that the DB CHECK rejects (raw error). Cashier session not tied to resort or to the opener.
- Duplicate: DB idempotency exists but the key is minted per request (`receivables.ts:180 randomUUID()`), so a retried submission creates a second receipt (WF-03/ACC-17). Duplicate `due_id` in one submission can over-allocate (ACC-05).
- Reversal: **`void_payment` has no UI** and would fail on the audit-action CHECK; it also never reverses the GL (ACC-01/ACC-03, WF-01). Receipts are effectively irreversible.

### 1.3 Cashier open / close
`finance/cashier/cashier-dialogs.tsx` → `openCashierSessionAction` / `closeCashierSessionAction` (`treasury.ts`) → `open_cashier_session` (one OPEN per cashbox) / `close_cashier_session` (expected = opening + receipts − payments; variance stored). Z-report PDF exists. Gaps: no confirm step when variance ≠ 0; variance not journaled; closer ≠ opener allowed; voided receipts never reverse `cash_transactions` (ACC-11).

### 1.4 Journal entry create / review / post / reverse
`finance/journals/new` → `createJournalEntryAction` → `create_journal_entry` (DRAFT) → `submitForReviewAction` → `postJournalEntryAction` → `post_journal_entry` (balance, period, account checks). Reverse: `journals/[id]/entry-actions.tsx` inline form with reason → `reverse_journal_entry`. Works; maker-checker is real. Gaps: reversal double-counts in every ledger report (ACC-02); no toast/redirect on journal pages (WF-15); no confirm dialog on reverse (WF-14).

### 1.5 Rent generation (leases)
`property/[unitId]/create-lease-dialog.tsx` → `create/activate/end/cancel_unit_lease`. Rent dues are generated only by `app/api/cron/lease-rent/route.ts` → `run_lease_rent_generation` (service role, skips demo, refuses without `CRON_SECRET`). `finance/dues/page.tsx:76-83` is deliberately read-only; there is no manual "run now" button. **In production the GitHub Actions job has never called the endpoint** because `CRON_SECRET` is unset (16/16 runs exit 0 with a warning; verified in run logs). Result: no lease rent dues have been generated by the scheduler since the workflow shipped, and the badge is green.

### 1.6 Member / unit statements
`lib/reports/account-statement-pdf.ts`, member-statement and unit-statement buttons, portal `/portal/statement` (E2E `portal-statement.spec.ts`). Works; formulas are independent of the ledger (ACC-13).

### 1.7 Credit notes
`finance/credit-notes/*` → `issueCreditNoteAction` → `issue_credit_note` (Dr revenue/VAT, Cr AR). Works only when a tax decision exists (tax enforcement on). Page is unreachable from navigation (WF-06) and credit notes never reduce collectible balance (ACC-06).

### 1.8 Service charges, commissions, deposits, handover
All wired: `finance/service-charges/levy-forms.tsx` (`issueLevy` via `useActionState`, no confirmation), `finance/commissions/commission-dialogs.tsx` (accrue/pay, voucher PDF; no cancel), `property/[unitId]/deposit-panel.tsx` (refund/deduct with reason), `property/[unitId]/handover-panel.tsx` (handover + snags). Posting rules match the decision records; open ADR items remain (0002, 0003, 0004).

### 1.9 Purchasing / expenses / bank reconciliation / budgets / fixed assets / projects / dunning / FX
All wired with callers; supplier-payment void has no UI; dunning delivery is human-performed (`dunning.ts:92-99` channels PHONE / EMAIL_EXTERNAL / WHATSAPP_EXTERNAL); bank reconciliation finalize is gated on balanced (`reconciliation-actions.tsx:34`).

### 1.10 Admin users / roles
`admin/users/*` → `inviteUserAction`, `changeUserRoleAction`, `updateUserStatusAction`, `removeUserAction`; `admin/roles/*` → `updateRolePermissionsAction`, `createRoleAction`. Functionally wired but **not authorized** (SEC-01/SEC-02): any member can escalate. Roles matrix shows 16 dead permission keys (§4). Invitation depends on Supabase SMTP (UNKNOWN in prod).

### 1.11 Member portal
Invite accept (`accept-invite-client.tsx:141 rpc("accept_member_invitation")`), OTP login (`login-form.tsx:78/118`), short links `/i/[slug]` (hard-coded `/en/` locale, WF-12), dues, payments (Fawry checkout), receipts, documents, statement, profile. Online payment: Fawry base URL is always sandbox (`lib/payments/resolve-credentials.ts:16, 99-102`); Paymob is configurable in settings but rejected by checkout (`online-payment-checkout.ts:17 z.enum(["FAWRY"])`) and has no webhook.

### 1.12 Import / export
`import/*` → `importPropertyCsvAction` + `/api/ai/import-map`. Exports are per-screen CSV/XLSX/PDF (40 files); no tenant-wide export despite the "100% data export" marketing claim.

### 1.13 Platform admin
`platform/organizations` (create, status, subscription), `platform/leads` (read-only latest 100 demo leads), `platform/audit` (read-only). No owner/member assignment UI on the organization page; no view of `contact_requests`; no onboarding queue (schema exists, no UI).

### 1.14 AI features
Seven `app/api/ai/*` routes check `getCurrentUser` only; no `has_permission`, no kill-switch; `ask-aqarbooks/route.ts:32` hard-codes a permission list including the non-seeded `finance.receivables.read`; `journal-propose` takes `organizationId` from the body with `user.id` fallback. `admin/ai-governance` is `useState`-only — toggles never persist (WF-04/WF-05). AI audit tables targeted by `lib/ai/governance.ts` do not exist (DB-06).

## 3. Navigation vs routes
Nav tree is inline in `app/[locale]/(app)/layout.tsx` (57 hrefs), pruned by `lib/auth/nav-permissions.ts`. Against 88 routes: no nav item points to a missing route; `/finance/credit-notes` is the only true orphan; one broken href (`/property/units`); locale-hardcoded redirects in `app/i/[slug]/route.ts`; routes with no inbound link: `/auth/verify-email`, `/platform` index, `/onboarding` (by design).

## 4. Permissions
Seeded 76 keys vs 55 checked in TypeScript. Checked but never seeded (6): `finance.accounts.read`, `finance.cashier.read`, `property.units.read`, `finance.receivables.read` (AI tool registry + ask route), `finance.expenses.view` (ap-aging, capex-opex report fallbacks), `finance.treasury.read` (cash-flow-forecast). Seeded but never checked in TS (27): 11 are enforced inside SQL (`finance.payments.void`, `finance.suppliers.void`, `property.leases.view`, `property.members.view`, `property.installments.manage`, `property.handover.read`, `finance.schedules.generate/manage`, `cashier.reconciliations.approve`, `purchasing.orders.approve`, `finance.tax_enforcement.manage`); 16 are fully dead and still appear in the roles matrix: `receivables.dues.create`, `receivables.allocations.manage`, `finance.reports.export`, `finance.reports.view`, `finance.payments.create`, `finance.audit.verify`, `finance.schedules.read`, `banking.reconciliations.manage`, `platform.audit.view`, `platform.organizations.manage`, `platform.subscriptions.manage`, `inventory.items.manage`, `inventory.adjustments.approve`, `inventory.transactions.create`, `purchasing.requests.create`, `property.installments.view`.

## 5. i18n and RTL
`messages/en.json` and `messages/ar.json` have identical key sets (24 leaf keys; namespaces `app, common, auth, dashboard, home`), but next-intl is used by only 3 files; 334 files use inline `isAr ? "…" : "…"` ternaries, so JSON parity is not meaningful and no tooling can detect a missing Arabic branch. Sampled presentational components showed no single-language leaks. RTL: `app/[locale]/layout.tsx:49, 180-181` sets `lang`/`dir` correctly. Default Next error screens are English/LTR (WF-11).
